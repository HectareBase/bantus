# ウィジェットアプリの計画

## 目的
Claude デスクトップでは、セッションに色やアイコンを付けたり、ショートカットを自由に割り当てたりできません。そこで、画面の端に置いておくサイドバー型のウィジェットで次のことを補います。

1. どのセッションが**対応待ち・処理中・待機中**かを、ひと目でわかるようにする
2. クリックやショートカットで、目的のセッションをすぐに開く
3. プロジェクト（フォルダ）ごとに色やアイコンを付けて見分ける

## 決まったこと
| 項目 | 決定 |
|---|---|
| 形 | **モニターの隅に表示するサイドバー型のウィジェット**が中心 |
| 見た目 | Windows 11 のデザインに合わせる（Fluent の色・角丸・フォント）。背景の不透明度を下げると、カードとタイトルバーだけが浮かんで見える |
| 処理中の表示 | 円形のプログレス（回り続けるリング） |
| 対応待ちの表示 | 点滅させる。そのときも CPU の使用率を低く抑える |
| 作り方 | **Electron**（Node.js 24 がこの PC にある） |
| 管理 | git で管理する。公開するときに**個人情報と日付が入らない**ようにする → [publishing.md](publishing.md) |

## 画面のイメージ（カード案 B-1）
```

│┌────────────┐│

││ > 停止中 4             ││  ← 停止中はたたむ
│└────────────┘│
│┌────────────┐│

│└────────────┘│
└──────────────┘
```

## 表示ルール
**色は状態を表す**（フォルダの色は使わない）
| 状態 | 色 | 印 | 左端の帯 |
|---|---|---|---|
| 対応待ち | 黄（警告色） | 点滅する点 | あり |
| 処理中 | 青（アクセントカラー） | 回るリング | あり |
| 待機（ターン完了） | 緑 | 塗りつぶした点 | なし |
| 停止中 | グレー | 中が空の円。文字も薄く | なし |

**カード（リポジトリ）**
- まとめる目印は `gitAnchors[].gitRoot`（リポジトリのフォルダ）。ワークツリーでも元のリポジトリを指すので、同じカードに入る。git の情報がないセッションは `originCwd`（元の作業フォルダ）でまとめる。同じフォルダなら、git の情報のあるなしにかかわらず 1 枚のカードになる
- カードの名前は、リポジトリのフォルダ名（`gitRoot` の末尾）
- 見出しの右に、いちばん急ぐ状態のバッジを出す（「要対応 n」→ なければ「処理中 n」→ なければ出さない）
- 並び順：対応待ちを含むカード → 処理中を含むカード → 最終更新が新しい順

**小見出し（ワークツリー）**
- カードの中に、ワークツリーのセッションが 1 件でもあれば、ワークツリーごとに小見出しを付ける。メインの作業場所は「メイン（ブランチ名）」。ブランチ名はリポジトリの `.git/HEAD` から読む
- ワークツリーの小見出しはブランチ名。`claude/` と末尾の英数字（`-8c38f8` など）は省き、マウスを乗せると元の名前を出す
- ワークツリーのセッションがないカードには、小見出しを付けない
- 小見出しの並び順も、カードと同じ（急ぐ順 → 新しい順）

**停止中**
- カードの一番下に「停止中 n」とまとめて、たたんでおく。開くと、ワークツリー名を添えた行で並ぶ

**たたんだ細いバー**
- リポジトリの頭文字の丸を縦に並べる。丸の縁を、そのリポジトリでいちばん急ぐ状態の色にする（対応待ちなら点滅）

その他
- 幅は 264px。たたむと 52px
- 行をクリックすると `claude://` リンクでセッションを開く
- 状態の判定は [session-status.md](session-status.md) のとおり

## Electron での作り方
| 要素 | 方法 |
|---|---|
| 背景 | 透明なウィンドウ（`transparent: true`、`frame: false`）に、CSS でテーマの背景色を塗る。透明なウィンドウには Mica を使えない（Acrylic と Mica の切り替えは廃止）。背景が 0% のときは、何もない所の上で `setIgnoreMouseEvents(true, { forward: true })` にしてクリックを後ろへ通す |
| 画面の端に固定 | 最初は、作業領域（`screen.getPrimaryDisplay().workArea`）の端に置く常に手前のウィンドウにする。ほかのウィンドウが重ならないよう**画面の領域を確保する**（AppBar、`SHAppBarMessage`）のは、FFI（`koffi`）で後から足す |
| ライト / ダーク | `nativeTheme.shouldUseDarkColors` と CSS の `prefers-color-scheme` |
| アクセントカラー | `systemPreferences.getAccentColor()` |
| フォント | `Segoe UI Variable`（日本語は `Yu Gothic UI`） |
| ホットキー | `globalShortcut` |
| トレイ | `Tray`（状態で色が変わるアイコン） |
| 通知 | `Notification`（対応待ちになったとき。設定で切り替え） |
| データの読み取り | メインプロセスで `fs.watch` を使って 2 つのフォルダを見張り、変化したときだけ読み直して、IPC で画面に送る。念のため、低い頻度（30 秒くらい）の読み直しも残す |
| セッションを開く | `shell.openExternal('claude://claude.ai/epitaxy/<ID>')` |

## CPU を抑えるための決まり
- アニメーションは CSS の `transform`（回転）と `opacity`（点滅）**だけ**を使う。GPU の合成だけで描かれるので、JavaScript もレイアウトの再計算も動かない
- `requestAnimationFrame` や `setInterval` でのアニメーションはしない
- 点滅はゆっくり（1 周期 1.2〜2 秒くらい）。OS の「アニメーション効果」がオフ（`prefers-reduced-motion`）なら、点滅をやめて色だけにする
- ウィジェットを隠しているとき、たたんでいるときは、アニメーションを止める（`animation-play-state: paused`、または表示しない）
- データは差分だけを画面に反映する。行全体を毎回描き直さない
- 目標：アイドル時の CPU 使用率 1% 未満（点滅中も含む）。タスクマネージャーと `app.getAppMetrics()` で測る

## 機能
**最初の版**（✅ はできたもの。詳しくは `app/README.md`）
- ✅ 状態ごとのセッション一覧（対応待ち → 処理中 → 待機 → 停止中）
- ✅ 円形プログレスと点滅
- ✅ クリックでセッションを開く
- ✅ リポジトリごとのカードと、ワークツリーごとの小見出し（色は状態だけを表す）
- ✅ 画面の端への配置（右 / 左）と、たたむ・広げる
- ✅ 設定ウィンドウ（カテゴリ分け。表示：位置、モニター、背景の不透明度、カードの不透明度）
- ✅ ライト / ダークの切り替えに追従

**次の版**
- ホットキー（一覧の表示、特定のセッションを開く）
- トレイのアイコン、対応待ちの通知
- 画面の領域の確保（AppBar）
- 設定のカテゴリを増やす（一覧、通知、ショートカット）

**やらないこと**
- Claude のデータファイルへの書き込み、アプリ本体の改造
- 認証情報を含むファイルを読むこと（[data-sources.md](data-sources.md) の「触ってはいけないもの」）

## フォルダの構成
Electron 版は `app/` に置きます。試作は `prototype/`、検証用のスクリプトは `tools/` にあります。

## 今ある試作（PowerShell と WPF）
`prototype/` にあります（使い方は `prototype/README.md`）。状態を記録する検証用のスクリプトは `tools/watch-status.ps1` です。Electron 版ができるまでは、こちらを使います。データを読む処理の考え方は、Electron 版にそのまま移します。
