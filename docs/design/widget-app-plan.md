# ウィジェットアプリの計画

## 目的
Claude デスクトップでは、セッションに色やアイコンを付けたり、ショートカットを自由に割り当てたりできません。そこで、画面の端に置いておくサイドバー型のウィジェットで次のことを補います。

1. どのセッションが**対応待ち・処理中・待機中**かを、ひと目でわかるようにする
2. クリックやショートカットで、目的のセッションをすぐに開く
3. プロジェクト（フォルダ）ごとに色やアイコンを付けて見分ける

## 決まったこと
| 項目 | 決定 |
|---|---|
| 形 | **モニターの隅に表示するサイドバー型のウィジェット**が中心 |
| 見た目 | Windows 11 のデザインに合わせる（Fluent の色・角丸・フォント）。背景の不透明度を下げると、カードとタイトルバーだけが浮かんで見える |
| 処理中の表示 | 薄い輪の上を、伸び縮みする弧が回る（Windows 11 の ProgressRing に近い動き。lucide にないので自前で描く） |
| 対応待ちの表示 | 点滅させる。そのときも CPU の使用率を低く抑える |
| 作り方 | **Electron**（Node.js 24 がこの PC にある） |
| 管理 | git で管理する。公開するときに**個人情報と日付が入らない**ようにする → [publishing.md](../publishing.md) |

## 表示ルール
**色は状態を表す**（フォルダの色は使わない）
| 状態 | 色 | 印 |
|---|---|---|
| 対応待ち | 黄（警告色） | 理由ごとのアイコンを点滅。許可は盾（`shield`）、回答は `keyboard`、ダイアログは `app-window`、ほかは `circle-alert` |
| 処理中 | 青（アクセントカラー） | 伸び縮みしながら回る弧 |
| 待機（ターン完了） | 緑 | 吹き出し（`message-square-more`） |
| 停止中 | グレー | `circle-minus`。文字も薄く |

印は lucide のアイコンで、14px にそろえる。塗りつぶした点は未読に見えるので使わない。

**左端の帯（未確認）**
- 前に見てから対応が必要になった行に出す。色は今の状態の色（対応待ちは黄、待機は緑）で、対応待ちの印と同じ速さで点滅させる
- 付ける：対応待ちになったとき（ウィジェットを起動した時点で対応待ちのときも）、処理中から待機になったとき
- 消す：行をクリックしたとき、トーストをクリックしたとき、処理中になったとき、対応待ちから待機・停止中になったとき（デスクトップ側で対応済み）
- Claude 本体で開いたときも消す。帯が付いたあとでそのセッションの `lastFocusedAt` が進んだら、本体のサイドバーや本体の通知から開いたものとみなす（サイドチャットで開いたときは親を開いたものとする）
- 本体で見ている最中に変わったときは付けない。今開いているセッションが変わり、Claude のウィンドウが前面にあるとき
- タスクバーの点滅は帯と切り離す。音・トーストと同じ「状態が変わった瞬間の 1 回だけの知らせ」で、同じ決まり（知らせる理由の設定、開いているセッションは知らせない、起動直後は知らせない、まとめて 1 回、続くときは間をあける）に従う。3 秒ほどで止め、オレンジのまま残さない。続けて知らせるときは止める時刻を延ばす。ウィジェットが前面にあるときは点滅させない
- ウィジェットの中だけで覚える。再起動すると、対応待ちの行以外は消える

**字下げ**
- 小見出し、行、折りたたみのボタンは、どれも「16px の印の列 + 文字」の並びにする。ワークツリーのあるなしで字下げを変えない。階層は小見出しの小さく薄い文字で表す

**カード（プロジェクト）**
- まとめる目印は `gitAnchors[].gitRoot`（リポジトリのフォルダ）。ワークツリーでも元のリポジトリを指すので、同じカードに入る。git の情報がないセッションは `originCwd`（元の作業フォルダ）でまとめる。同じフォルダなら、git の情報のあるなしにかかわらず 1 枚のカードになる
- カードの名前は、リポジトリのフォルダ名（`gitRoot` の末尾）
- 見出しの右に、いちばん急ぐ状態のバッジを出す（「要対応 n」→ なければ「処理中 n」→ なければ出さない）
- 並び順：対応待ちを含むカード → 処理中を含むカード → 最終更新が新しい順

**小見出し（ワークツリー）**
- カードの中に、ワークツリーのセッションが 1 件でもあれば、ワークツリーごとに小見出しを付ける。元のフォルダの小見出しは、家のアイコンとブランチ名（わからなければ「元のフォルダ」）。ブランチ名はリポジトリの `.git/HEAD` から読む
- ワークツリーの小見出しはブランチ名。`claude/` と末尾の英数字（`-8c38f8` など）は省き、マウスを乗せると元の名前を出す
- ワークツリーのセッションがないカードには、小見出しを付けない
- 小見出しの並び順も、カードと同じ（急ぐ順 → 新しい順）

**折りたたみ（上限を超えた分と停止中）**
- ワークツリーのグループごとに、見せるセッションの数に上限を設ける（設定で 3 / 5 / 8 / すべて。既定は 5）。急ぐ順に上から見せ、残りは停止中と一緒に折りたたみに入れる
- 上限を超えても見せるもの
  - 対応待ちと常に表示のもの：上限の枠を先に使う
  - 未確認（左端の帯）と今開いているもの：空いた枠がなければ枠の外に足す（ほかの行を押し出してちらつかせない）
- まとめ方は設定で選ぶ
  - プロジェクト（既定）：カードの一番下に 1 つ。行にはワークツリー名を添える
  - ワークツリー：小見出しごとに、そのグループの一番下に置く。停止中しかないワークツリーにも小見出しを出す
- 折りたたみのボタンは、左に「すべて表示」（開いているときは「折りたたむ」）、右端に状態ごとの印と件数を並べる（処理中・待機・停止中。対応待ちは隠さないので出ない）。印と色は行と同じで、処理中の弧は回さない。「ほか n 件・停止中 m」の文字はツールチップに出す
- 開けるのは 1 つだけ。行を選んだとき、外をクリックしたとき、Esc を押したときに閉じる。折りたたみから選んだ行は、今開いているものとして一覧に上がる
- 行にマウスを乗せると右端に星が出て、押すと「常に表示」になる（停止中でも一覧に残る）。保存先は Bantus の設定で、一覧から消えたセッションの分は自動で外す
- ショートカットで回るのは、折りたたみの外の行だけ（常に表示の停止中も入る）

その他
- 幅は 264px（内側の端をドラッグして変える）
- 行をクリックすると `claude://` リンクでセッションを開く

**ショートカットでの巡回（`Ctrl+Alt+N`）**
- 押すたびに、未確認（左端の帯）の行を、表示順で上から開く。開くと帯が消えるので、続けて押すと次の未確認の行へ進む。Claude のウィンドウが前面にないときも同じ（未確認は処理中より急ぐため）
- 未確認の行がなければ、今開いているセッションの次の行を表示順で開く（最後の行の次は先頭）
- 今開いているセッションと停止中のものは選ばない
- 未確認の行がなく Claude のウィンドウが前面にないときは、次へ進まずに今開いているセッションを開き直して前面に出す（もう一度押すと次へ進む）。前面のウィンドウは、常駐させた PowerShell で `GetForegroundWindow` を呼び、プロセス名が `claude` かで判断する。調べられなかったときは前面にあるものとして扱う
- 開く先は画面側が決める（未確認の帯を画面側で覚えているため）。メインプロセスはキーを受けて、Claude が前面にあったかと一緒に画面に伝えるだけ
- 状態の判定は [session-status.md](../research/session-status.md) のとおり

## Electron での作り方
| 要素 | 方法 |
|---|---|
| 背景 | 透明なウィンドウ（`transparent: true`、`frame: false`）に、CSS でテーマの背景色を塗る。透明なウィンドウには Mica を使えない（Acrylic と Mica の切り替えは廃止）。背景が 0% のときは、何もない所の上で `setIgnoreMouseEvents(true, { forward: true })` にしてクリックを後ろへ通す |
| 画面の端に固定 | 最初は、作業領域（`screen.getPrimaryDisplay().workArea`）の端に置く常に手前のウィンドウにする。ほかのウィンドウが重ならないよう**画面の領域を確保する**（AppBar、`SHAppBarMessage`）のは、FFI（`koffi`）で後から足す |
| ライト / ダーク | `nativeTheme.shouldUseDarkColors` と CSS の `prefers-color-scheme` |
| アクセントカラー | `systemPreferences.getAccentColor()` |
| フォント | `Segoe UI Variable`（日本語は `Yu Gothic UI`） |
| ホットキー | `globalShortcut` |
| トレイ | `Tray`（状態で色が変わるアイコン） |
| 通知 | 音は Web Audio で合成（ファイルは同梱しない）。トーストは `Notification`（`silent: true`）。対応待ち・完了ごとに設定で切り替え |
| データの読み取り | メインプロセスで `fs.watch` を使って 2 つのフォルダを見張り、変化したときだけ読み直して、IPC で画面に送る。念のため、低い頻度（30 秒くらい）の読み直しも残す |
| セッションを開く | `shell.openExternal('claude://claude.ai/epitaxy/<ID>')` |

## CPU を抑えるための決まり
- アニメーションは CSS の `transform`（回転）と `opacity`（点滅）**だけ**を使う。GPU の合成だけで描かれるので、JavaScript もレイアウトの再計算も動かない
- `requestAnimationFrame` や `setInterval` でのアニメーションはしない
- 点滅はゆっくり（1 周期 1.2〜2 秒くらい）。OS の「アニメーション効果」がオフ（`prefers-reduced-motion`）なら、点滅をやめて色だけにする
- ウィジェットを隠しているときは、アニメーションを止める（`animation-play-state: paused`、または表示しない）
- データは差分だけを画面に反映する。行全体を毎回描き直さない
- 目標：アイドル時の CPU 使用率 1% 未満（点滅中も含む）。タスクマネージャーと `app.getAppMetrics()` で測る

## 機能
**最初の版**（✅ はできたもの。詳しくは `app/README.md`）
- ✅ 状態ごとのセッション一覧（対応待ち → 処理中 → 待機 → 停止中）
- ✅ 円形プログレスと点滅
- ✅ クリックでセッションを開く
- ✅ プロジェクトごとのカードと、ワークツリーごとの小見出し（色は状態だけを表す）
- ✅ 画面の端への配置（右 / 左）。たたむ機能は作ったが、使わないので外した
- ✅ 設定ウィンドウ（カテゴリ分け。全体：位置、見た目。カードの表示：一覧、並び順、行に出すもの）
- ✅ ライト / ダークの切り替えに追従

**次の版**
- ✅ ホットキーで未確認のセッションを巡回する
- ホットキー（一覧の表示、特定のセッションを開く）、キーを設定で変える
- ✅ トレイのアイコン
- ✅ 対応待ちと完了の通知（音とトースト。まとめて 1 回、続くときは数秒あける。起動直後と、前面で開いているセッションは知らせない）
- 画面の領域の確保（AppBar）
- 設定のカテゴリを増やす（✅ 通知。残りは一覧、ショートカット）

**やらないこと**
- Claude のデータファイルへの書き込み、アプリ本体の改造
- 認証情報を含むファイルを読むこと（[data-sources.md](../research/data-sources.md) の「触ってはいけないもの」）

## フォルダの構成
Electron 版は `app/` に置きます。試作は `prototype/`、検証用のスクリプトは `tools/` にあります。

## 今ある試作（PowerShell と WPF）
`prototype/` にあります（使い方は `prototype/README.md`）。状態を記録する検証用のスクリプトは `tools/watch-status.ps1` です。Electron 版ができるまでは、こちらを使います。データを読む処理の考え方は、Electron 版にそのまま移します。
