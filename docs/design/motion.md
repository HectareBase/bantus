# アニメーション効果（ひかえめ）

ウィジェットの CPU を減らすため、動き続ける表示を止める設定を足します。止めたものの代わりに、状態を行の色と枠で示します。**既定は標準**（今までの見た目）です。

## ねらい
ウィジェットはいつも出ている透明なウィンドウです。処理中の輪、光の帯、点滅が動いている間は、コマごとにウィンドウ全体を合成し直すので、何もしていなくても CPU を使い続けます。コマ数を落としても（`steps()`、`app/src/renderer/styles.css` の `.progress-ring` のコメント）、1 コアの 1 割を超えていました。

## 動かし方
- 設定の「見た目」→「状態の色」→「アニメーション効果」（標準／ひかえめ）。設定の名前は `motion`（`'full' | 'subtle'`、`app/src/shared/settings.ts`）
- `status-colors.ts` の `applyMotion` が `<html data-motion="subtle">` を付け、CSS が見た目を切り替える。ウィジェット、一覧（めくれ）、設定画面の見本の行で同じ
- OS の「動きを減らす」（`prefers-reduced-motion`）のときも、設定にかかわらず `data-motion="subtle"` を付ける
- 処理中のアイコンは、回る輪と砂時計（lucide の `hourglass`）の両方を入れておき、CSS でどちらかを見せる（`status-icon.ts`）。隠した輪は動かない。設定を切り替えても作り直さない

## 止めるもの、残すもの
| | ひかえめのとき |
|---|---|
| 処理中の輪の回転と弧の伸び縮み | 止める。砂時計を出す |
| 処理中のセッション名を流れる光の帯 | 止める。名前は標準の帯の下地と同じ薄い色（`--text-tertiary`）で出す |
| 対応待ちのアイコンの点滅 | 止める |
| 未確認の行の左端の帯の点滅 | 止める。点灯したままの太い帯（4px）にする |
| 並べ替えの動き（`flip.ts`） | 残す |
| 未確認になったときに一度だけ横切る光（`sweep.ts`） | 残す |
| めくれの出入り、ピンの傾き | 残す |

一度きりの動きは、終わればコマを描かないので残します。

## 見た目
- 対応待ちと待機中の行に、状態の色の塗りと 1px の枠を付ける。対応待ちを強く、待機中を弱くする
- 今開いている行（`data-focused`）は塗りと枠を濃くし、斜線を重ねる。斜線は状態の塗りの上でも見えるよう、標準より濃くする（`--stripe-a`。設定の濃さの倍率 `--hl` はそのままかける）
- 未確認の行（`data-attention`）は、状態の色の 2px の枠にする
- 処理中・停止中の行には塗りと枠を付けない。開いていれば、標準と同じ灰色の塗りと斜線
- 待機中でバックグラウンドの作業が動いている行も、処理中と同じく塗りと枠を付けない（放っておいてよい行のため）。印は処理中と同じ青い砂時計になり、文字（「処理中」と「バックグラウンドで作業中」）で見分ける
- 保留の行と、保留のカードの中の行は、標準と同じ見た目のまま

| | 塗り | 枠 |
|---|---|---|
| 対応待ち | 6% | 30% |
| 待機中 | 4% | 22% |
| 対応待ち（開いている） | 16% | 60% |
| 待機中（開いている） | 13% | 45% |

| 斜線（`--stripe-a`） | 標準 | ひかえめ |
|---|---|---|
| ライト | 0.025 | 0.07 |
| ダーク | 0.03 | 0.08 |

## 確かめた結果
見本データ（`all-states`、ダーク、GPU は使わない）で、標準とひかえめを交互に 3 回ずつ起動しました。起動して 15 秒待ち、続く 30 秒の CPU 時間をプロセスの種類ごとに足しました。CPU は 1 コアに対する割合です。

| 回 | 標準：合計 | 描画のプロセス | GPU のプロセス | ひかえめ：合計 |
|---|---|---|---|---|
| 1 | 14.1% | 7.5% | 6.4% | 0.2% |
| 2 | 12.2% | 6.8% | 5.2% | 0.7% |
| 3 | 14.2% | 7.8% | 6.0% | 0.4% |

- 標準のときは、描画のプロセスと GPU のプロセスがほぼ半分ずつ使う。GPU の設定が「使わない」でも、画面の合成で GPU のプロセスが動く
- ひかえめでは、どちらもほぼ 0 になる。ウィジェットの CPU は、ほとんどが動き続ける表示の分だった
- 見本データでは対応待ちの行がすべて未確認で出るので、点滅は実際より多い。実際のデータでは差が小さいことがある。ただ処理中の行が 1 つでもあれば、輪と光の帯は動き続ける

### 確かめられなかったこと
- 見本データでは対応待ちの行がすべて未確認になるので、未確認でない対応待ちの行（開いている行と、開いていない行）の塗りと枠は、画面で見ていない
- 実際のデータでの CPU は測っていない
