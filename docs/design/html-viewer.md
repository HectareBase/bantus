# HTML ビューア

ウィジェットのカードの一覧の下に、今開いているセッションの作業フォルダにある HTML ファイルを出します。セッションが書いたレポートや見本のページを、ブラウザーに切り替えずに読むためのものです。既定はオフで、設定の「HTML ビューア」でオンにします。

## 表示のしかた
- **iframe は使わない。** ウィジェットの画面には preload の API（`window.widget`）があり、同じ画面の iframe からは、表示した HTML のスクリプトがその API に手が届いてしまうため
- メインプロセスが `WebContentsView` を作り、`win.contentView.addChildView` でウィジェットに重ねる（`app/src/main/viewer.ts`）
  - `webPreferences`：preload なし、`sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`、`webviewTag: false`
  - パーティションは `viewer`（`persist:` を付けないので、クッキーやストレージをディスクに書かない。ほかのウィンドウとも分かれる）
  - 背景は白。背景のない HTML でも、ウィジェットの背景が透けて読みにくくならないようにする
- 画面側に場所取り用の `#viewer-slot` を置く。その位置と大きさを `ResizeObserver` とウィンドウの `resize` で測り、IPC（`viewer-bounds`）で送る。メインは表示の拡大率（`zoom`）をかけて `setBounds` で合わせる
- ビューはウィンドウに足して（`addChildView`）から隠す。足す前に `setVisible(false)` にすると、あとで出してもページが隠れたまま（描かれない）になることがあった
- ビューにも表示の拡大率をかける（読み込み終えるたびと、設定を変えたとき）

## 表示するファイル
- 対象は、今開いているセッション（`renderer/model.ts` の `resolveFocus()` の結果）の `SessionView.workDir` から見た、設定の相対パス（`viewerPath`）。元のフォルダのセッションならリポジトリのルートから見る（`workDir` がそうなっている）
- 画面からはセッションの ID だけを送る（`viewer-target`）。パスはメインプロセスが自分の一覧から引く（`app/src/main/viewer-target.ts`）。画面が任意のファイルを開けないようにするため
- 出せないときは、HTML の代わりに理由を出す

| 様子（`ViewerState.kind`） | 出すもの |
|---|---|
| `noSession` | 開いているセッションがない |
| `noPath` | ファイルの場所を決めていない |
| `noDir` | セッションに作業フォルダがない（git 管理でないなど）：「このセッションでは表示できません」 |
| `archived` | カードをアーカイブしている（ビューは閉じる） |
| `missing` | ファイルがない：「ファイルがありません」と、探したパス |
| `ok` | 表示している |

- 元のフォルダの同じファイルに代えて出すことはしない（どのワークツリーのものか取り違えるため）
- 同じワークツリー（作業フォルダ）の中でセッションを切り替えても、何もしない。ビューは作業フォルダごとに 1 つ
- 開いているセッションは、行をクリックしてから本体のファイルが追いつくまで、クリックした行を仮に使う（`resolveFocus`）。仮の値が 30 秒で切れると、本体のファイルの値に戻る

### パスの検査（`app/src/shared/viewer-path.ts`）
設定画面（入力を確定したとき）と、設定の保存（`normalizeSettings`）と、メインプロセスで同じ検査を通す。

- 受け付けないもの：絶対パス（`/`、`\\server`、`~`）、ドライブ名（`C:`）、`..` でルートの外に出るもの、`.html`／`.htm` 以外、使えない文字（制御文字、`<>"|?*:`）、末尾が点か空白の部分
- 受け付けたものは、区切りを `/` にそろえ、`.` と途中の `..` を畳んで保存する
- 開く前に、作業フォルダとファイルの `realpath` をとり、ファイルが作業フォルダの中にあるかをもう一度確かめる（リンクで外を指していれば `missing`）。フォルダはファイルとして開かない

## スクロールの保持
- 作業フォルダごとにビューを残し、切り替えでは表示と非表示を入れ替えるだけにする（スクロールの位置も、ページの中の状態もそのまま）
- 残すのは最近使った 4 つまで（`VIEWER_KEEP`）。あふれたものは閉じる前に `scrollX`／`scrollY` を記録し（32 件まで）、次に同じファイルを読み込み終えたら戻す
  - 中身が後から描かれるページもあるので、高さが足りるまで 100ms ごとに試す（最大 3 秒）
  - スクロールの読み書きは隔離した世界（`executeJavaScriptInIsolatedWorld`）で動かす。ページのスクリプトが `scrollTo` などを書き換えていても影響されない
- ワークツリーが消えたとき（作業フォルダがない、一覧にない）、カードをアーカイブしたとき、ビューアをオフにしたとき、設定のパスを変えたときは、ビューを閉じ、位置も忘れる

## ファイルが変わったとき
- ファイルの入ったフォルダを `fs.watch` で見張り（エディターは保存のときにファイルを置き換えることがあり、ファイルそのものを見張ると途切れる）、そのファイルの名前の変化だけを拾う
- 300ms 待ってから読み込み直す。読み込み直してもスクロールの位置を保つ
- 設定 `viewerAutoReload`（既定はオン）で切り替える。オフのときは見張らない
- 見出しの「読み込み直す」は、設定にかかわらず読み込み直す。あわせて、ファイルができた・消えたも調べ直す
- ファイルがないときは見張っていないので、できたことは一覧の更新か「読み込み直す」で気づく

## 配置
- カードの一覧の下に、上下にドラッグできるつまみ、細い見出し、HTML の順に置く
- 見出し：ファイル名、ワークツリー名（元のフォルダならブランチ名）、「読み込み直す」「ブラウザーで開く」「畳む」
  - 「ブラウザーで開く」は `shell.openExternal` に `file://` の URL を渡す（いつものブラウザーで開く）
- 高さは `viewerHeight`（CSS px）として保存する。設定画面には出さない。範囲は 80px から「ウィンドウの高さ − 160px」まで（`clampViewerHeight`）。ドラッグ中は保存せず、離したときに保存する
- 「畳む」の状態は `viewerCollapsed` として保存する。畳むと見出しだけを残し、ビューを隠す
- ウィジェットを隠したときと最小化したときは、ウィンドウと一緒にビューも隠れる

## 設定
カテゴリ `viewer`（アイコンは lucide の `panel-bottom`）。

| 項目 | 種類 | 既定 |
|---|---|---|
| `viewerEnabled` | segmented（出す／出さない） | 出さない |
| `viewerPath` | `text`（stacked。入力を確定したとき（`change`）に検査し、だめなら理由を入力欄の下に出して保存しない） | 空 |
| `viewerAutoReload` | segmented（反映する／反映しない） | 反映する |

- `viewerPath` と `viewerAutoReload` には `enabledBy: 'viewerEnabled'` を付ける
- パスはすべてのリポジトリで共通の 1 つ。リポジトリごとに変えるときは、リポジトリの目印（`repoKey`）からパスへの表（例：`viewerPaths`）を設定に足し、`resolveViewerTarget` で先にそちらを引く

## 表示した HTML にさせないこと
- ページの移動（`will-navigate`、`will-redirect`）は止める。http(s) のリンクは `shell.openExternal` でいつものブラウザーに渡す。ページの中のリンク（`#`）はそのまま動く
- `setWindowOpenHandler` で新しいウィンドウは開かせず、http(s) ならブラウザーに渡す
- 権限の要求（位置情報、通知、カメラなど）はすべて断る（`setPermissionRequestHandler`、`setPermissionCheckHandler`、`setDevicePermissionHandler`）
- ダウンロードはさせない（`will-download`）。`<webview>` も付けさせない
- JavaScript は動かす

## 見本データ
`npm run debug` の見本データ（`app/fixtures/all-states.json`）の一部のセッションに、`workDir` を見本データのファイルから見た相対パスで書いた（`fixtures/viewer/<名前>`）。設定でビューアをオンにし、場所を `report.html` にすると見られる。

| カード | 様子 |
|---|---|
| my-app の main、fix-login、spike、very-long-branch、task-a、task-b | 見本の HTML を表示（6 つあるので、4 つを超えて閉じる動きも確かめられる） |
| new-api | フォルダはあるがファイルがない（`missing`） |
| そのほか | 作業フォルダがない（`noDir`） |

見本の HTML は、半分の節を 0.5 秒後に描く（スクロールを戻すときに、高さが足りるまで待つかを確かめる）。外部のリンク、新しいウィンドウのリンク、ほかのファイルへのリンク、位置情報の要求を並べている。

見本データのときは、作業フォルダで git を動かさない（見本の `changes` をそのまま出す）。

## 確かめたこと
見本データで起動し、リモートデバッグ（CDP）で操作して確かめた。

- 切り替え：別のワークツリーに切り替えると表示が替わり、同じワークツリーの中の切り替えでは読み込み直さない
- スクロールの保持：切り替えて戻っても位置が残る。4 つを超えて閉じたものも、開き直すと位置が戻る（後から描かれる位置でも戻る）
- ファイルの変更：書き換えると読み込み直し、位置を保つ。オフのときは読み込み直さず、「読み込み直す」で読み込み直す
- 高さのドラッグ、上限と下限、畳む、設定のオンオフ（オフですべてのビューを閉じる）、カードのアーカイブでビューを閉じる
- 移動、新しいウィンドウ、位置情報と通知の要求が止まり、ページから `require` や `window.widget` に届かない

確かめていないこと：本物のマウスで、つまみをビューの上までドラッグしたとき（CDP の入力はウィジェットの画面に直接届くので、ビューの上を通るときの動きは見ていない）。また、確かめた環境では Windows の遮蔽の判定（`CalculateNativeWinOcclusion`）が、新しく作ったウィンドウとビューを「隠れている」と見なして描かなかった。判定を切って起動すると描かれた。新しく作った普通のウィンドウでも同じだったので、そのときの画面の状態によるものと見ているが、ふだんの起動で描かれるかは画面で確かめる。
