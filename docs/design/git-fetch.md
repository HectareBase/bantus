# リモートの取得（git fetch）と git の設定

ウィジェットが定期的に `git fetch` を動かし、リモートからの遅れと、リモートでのマージを見分けられるようにします。あわせて、設定画面に git のカテゴリを足します。

## ねらい
- 元のフォルダ（main）のカードに、リモートからの遅れ（`arrow-down`）を出す。今は push していないコミット（`arrow-up`）だけ
- GitHub でマージしたワークツリーも「マージ済み」と分かるようにする。今は手元の main と比べるので、手元に取り込むまで分からない（[worktree-cards.md](worktree-cards.md) の「git：元のブランチからの遅れとマージ済み」）
- squash マージは、これでも見分けられない。見分けるには PR の状態を読む別の案が要る

## 方針との関係
今のウィジェットは「リポジトリを読むだけ」「読んだ内容をネットワークに送らない」です（[data-usage.md](data-usage.md)）。fetch は次の点でこれを広げます。

| 変わること | 中身 |
|---|---|
| `.git` に書く | `refs/remotes/<リモート>/*` と取ってきたオブジェクト。作業中のファイル、インデックス、ローカルのブランチ、HEAD、stash には触れない |
| ネットワークを使う | ユーザーがリポジトリに設定したリモートの URL に、git の通信をする。Bantus が読んだもの（セッション、会話）は送らない |

このため、**既定はオフ**にし、設定でオンにしたときだけ動かします。VS Code の `git.autofetch` と同じ扱いです。

## 動かし方
```
git -C <リポジトリ> -c credential.interactive=never fetch --no-auto-gc --no-auto-maintenance --no-write-fetch-head --quiet <リモート>
```
環境変数：`GIT_TERMINAL_PROMPT=0`、`GCM_INTERACTIVE=never`

| 項目 | 決まり | 理由 |
|---|---|---|
| 単位 | リポジトリ（`commonDir`）ごとに 1 回 | ワークツリーは参照を共有している |
| 対象 | アーカイブしていないカードが 1 つ以上あるリポジトリ | 見えていないリポジトリのために通信しない |
| リモート | 元のフォルダのブランチ（`mainBranch`）の追跡先のリモート（`branch.<名前>.remote`）。なければ取得しない | `--all` だと、ユーザーが使っていないリモートにまで通信する |
| `--no-auto-gc --no-auto-maintenance` | 付ける | fetch のついでに `.git` を詰め直さない |
| `--no-write-fetch-head` | 付ける | ユーザーが手で使う `FETCH_HEAD` を上書きしない |
| `--prune` | 付けない | リモートで消えたブランチの写しを勝手に消さない（ユーザーの `fetch.prune` の設定には従う） |
| ログインの画面 | 出さない（上の `-c` と環境変数） | 認証が切れていると、Git Credential Manager の画面が勝手に出るため |
| 待ち行列 | `git status` とは別の待ち行列にし、一度に 1 つずつ | 通信は遅いので、変更の件数の更新を止めない |
| 打ち切り | 60 秒 | |
| 間隔 | 設定の値（5 / 10 / 30 分、既定 10 分）。リポジトリごとに、最後に試した時刻から数える | |
| 初回 | 起動から（または設定でオンにしてから）1 分後 | 起動直後の読み込みと重ねない |
| 処理中のセッション | あっても取得する。ロックで失敗したらやり直す（下の「失敗したとき」） | 見送ると、セッションが多いときにいつまでも取得できない |
| 終わったあと | そのリポジトリの作業フォルダを、すべて「古い」として調べ直す | 遅れの数を更新するため |

### 失敗したとき
| 失敗 | 扱い |
|---|---|
| ロック（`cannot lock ref`、`index.lock`）。Claude が同時に push や fetch をしていた | 1 分後に 1 度だけやり直す。それでもだめなら次の回 |
| 通信できない（オフライン、タイムアウト） | 次の回まで待つ。何も出さない |
| 認証の失敗（`Authentication failed`、`could not read Username`） | そのリポジトリは、ウィジェットを開き直すか設定の「今すぐ取得」を押すまで止める。設定画面に出す |
| リモートがない、リポジトリが消えた | 取得しない |

失敗の内容はログに出しません。設定画面に出すのは、リポジトリ名と失敗の種類だけです。

## 表示
| 場所 | 今 | 変えたあと |
|---|---|---|
| 元のフォルダのカード | `arrow-up`（push していないコミット） | 取得がオンなら、`arrow-down`（追跡するブランチからの遅れ）も出す。数は `git status --branch` の `# branch.ab` の `-B`（今は読み捨てている） |
| ワークツリーのカードの遅れ | 手元の元のブランチと比べる | 変えない（ワークツリーは手元の main から切るので、比べる先は手元のままがよい） |
| ワークツリーのマージ済み | 手元の元のブランチに、マージコミットで入った | 手元の元のブランチ**か**、そのリモートの写し（`refs/remotes/<リモート>/<元のブランチ>`）に入った |
| 印のツールチップ | 「push していないコミット：1」 | 元のフォルダには「origin/main からの遅れ：3」を足す |

取得がオフのときは、元のフォルダの遅れを出しません。`refs/remotes` の写しが古いまま残っていて、数が実際と合わないためです。

## 設定画面
カテゴリ「git」（アイコン `git-branch`）を足し、「カードの表示」と「通知」の間に置きます。

| 見出し | 項目 | 形 | 既定 |
|---|---|---|---|
| リモートの取得 | 定期的に取得する | オン / オフ | オフ |
| | 間隔 | 5 分 / 10 分 / 30 分 | 10 分 |
| | 今すぐ取得 | ボタン。横に「最後の取得：3 分前」、失敗したリポジトリがあれば名前と種類 | |
| 変更の印 | カードに変更の印を出す | 出す / 出さない | 出す |
| | 未追跡のファイルを数える | 数える / 数えない | 数える |

- 「今すぐ取得」と最後の取得の結果を出すために、設定の型に新しい種類（`action`）を足す。今はスライダーや選択肢しかない
- 取得をオフにしたら、待ち行列を空にし、遅れの数を消す
- 「今すぐ取得」は設定画面にだけ置く。トレイのメニューには置かない

## 手で確かめること
- オフラインで動かしても、エラーの窓が出ず、ウィジェットが止まらない
- 認証が切れたリポジトリで、ログインの画面が出ない
- Claude が push している最中に取得が重なっても、どちらも壊れない（失敗しても、次の回に取れる）
- GitHub でマージコミットを作ってマージしたワークツリーが、手元の main に取り込まずに「マージ済み」になる
- `FETCH_HEAD` の更新時刻が変わらない
