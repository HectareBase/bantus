# コミットされていない変更の表示

ウィジェットのカードに、作業フォルダごとの「コミットされていない変更」の件数を出します。コードは `app/src/main/git-status.ts`（調べる）と `app/src/renderer/model.ts`（並べる）です。

## どこから読むか
- Claude デスクトップのデータ（`local_*.json`）には、変更の有無や件数を表す項目がありません。`postTurnSummary.status_detail` に「not committed」のような文が入ることはありますが、形が決まっていないので使いません。
- そこで、ウィジェットが作業フォルダで `git status` を実行して数えます。

## 調べるフォルダ
セッションごとではなく、**作業フォルダごとに 1 回**調べます。同じフォルダのセッションは同じ結果を使います。

| セッション | 調べるフォルダ |
|---|---|
| アプリが作ったワークツリー | `worktreePath` |
| リポジトリの外のワークツリー（`git worktree add`） | `gitAnchors[0].gitRoot` |
| リポジトリのフォルダで作業 | 元のリポジトリのフォルダ |
| git 管理でない（`gitAnchors` が空） | 調べない |

## 実行のしかた
```
git --no-optional-locks -C <フォルダ> status --porcelain=v2 --branch
```
- 普通の `git status` は、ついでに `.git/index` を書き直すことがあります（`index.lock` を取る）。`--no-optional-locks`（と環境変数 `GIT_OPTIONAL_LOCKS=0`）を付け、リポジトリに書き込まず、Claude 自身の git 操作ともぶつからないようにします。
- 非同期で、一度に 1 つずつ動かします。5 秒で打ち切ります。コンソールの窓は出しません（`windowsHide`）。
- git が見つからない、タイムアウトした、git 管理でなくなった、などで失敗したときは、印を出しません。
- 手元のリポジトリで測ると、1 か所あたり約 50ms でした。

## 数え方
| 出力の行 | 数える先 |
|---|---|
| `1 ...`（変更）、`2 ...`（名前の変更・コピー）、`u ...`（未解決の衝突） | 変更 |
| `? ...` | 未追跡（`.gitignore` に入っているものは出ない） |
| `# branch.ab +A -B` | push していないコミット（A）。追跡するブランチがなければ行がなく 0 |

印には、この 3 つをそれぞれアイコンと件数で並べます（0 のものは出さない）。

## いつ調べるか
セッションの一覧を読み直すたび（ファイルの変化と 30 秒おきの読み直し）に、次のフォルダだけを調べ直します。

- まだ調べていないフォルダ
- 結果が古くなったフォルダ：動いているセッションがあれば 30 秒、停止中のセッションだけなら 5 分
- 処理中のセッションが処理中でなくなったフォルダ（ターンが終わり、変更が増えたかもしれない）

調べ終えて結果が変わったら、一覧を画面に送り直します。作業フォルダを `fs.watch` で見張ることはしません（`node_modules` などで通知が多すぎるため）。

## 表示
今の色は状態だけを表すので、印は灰色の枠です（案 A）。中に内訳を lucide のアイコンと件数で並べます。

| アイコン | 意味 |
|---|---|
| `file-pen-line` | 変更 |
| `file-plus` | 未追跡 |
| `arrow-up` | push していないコミット |
| `arrow-down` | 元のブランチからの遅れ（ワークツリーだけ） |

- カード（ワークツリーと元のフォルダ）の見出しの右。印の 4 つ目に、元のブランチからの遅れ（`arrow-down`）も出す。調べ方は [worktree-cards.md](worktree-cards.md) の「git：元のブランチからの遅れとマージ済み」
- 印のツールチップ、セッションのツールチップ：「コミットされていない変更：変更 3・未追跡 2」「push していないコミット：1」「元のブランチからの遅れ：4」
- すべて 0 のフォルダ、まだ調べていないフォルダには印を出しません
