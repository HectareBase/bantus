# コミットされていない変更の表示

ウィジェットのカードに、作業フォルダごとの「コミットされていない変更」の件数を出します。コードは `app/src/main/git-status.ts`（調べる）と `app/src/renderer/model.ts`（並べる）です。

## どこから読むか
- Claude デスクトップのデータ（`local_*.json`）には、変更の有無や件数を表す項目がありません。`postTurnSummary.status_detail` に「not committed」のような文が入ることはありますが、形が決まっていないので使いません。
- そこで、ウィジェットが作業フォルダで `git status` を実行して数えます。

## 調べるフォルダ
セッションごとではなく、**作業フォルダごとに 1 回**調べます。同じフォルダのセッションは同じ結果を使います。

| セッション | 調べるフォルダ |
|---|---|
| アプリが作ったワークツリー | `worktreePath` |
| リポジトリの外のワークツリー（`git worktree add`） | `gitAnchors[0].gitRoot` |
| リポジトリのフォルダで作業 | 元のリポジトリのフォルダ |
| `gitAnchors` が空、またはない | 作業フォルダ（`originCwd`、なければ `cwd`）から上へ `.git` を探す。見つからなければ git 管理でないとして調べない |

## 実行のしかた
```
git --no-optional-locks -C <フォルダ> status --porcelain=v2 --branch
```
- 普通の `git status` は、ついでに `.git/index` を書き直すことがあります（`index.lock` を取る）。`--no-optional-locks`（と環境変数 `GIT_OPTIONAL_LOCKS=0`）を付け、リポジトリに書き込まず、Claude 自身の git 操作ともぶつからないようにします。
- 非同期で、一度に 1 つずつ動かします。5 秒で打ち切ります。コンソールの窓は出しません（`windowsHide`）。
- 失敗したときは、理由を覚えて注意の印で知らせます（下の「失敗の表示」）。作業フォルダがもうないときは、失敗ではなく「ワークツリーを消した」として扱います。
- 手元のリポジトリで測ると、1 か所あたり約 50ms でした。
- ワークツリーでは、このほかに元のブランチからの遅れとマージ済みを `rev-list` などで調べます。ただし、ワークツリーの先頭と比べる ref の先頭のコミットが前と同じなら、前の答えを使い回して git を起動しません（[worktree-cards.md](worktree-cards.md)）。プロセスを検査するセキュリティ製品のある PC では、git の起動そのものが重いためです。

## 数え方
| 出力の行 | 数える先 |
|---|---|
| `1 ...`（変更）、`2 ...`（名前の変更・コピー）、`u ...`（未解決の衝突） | 変更 |
| `? ...` | 未追跡（`.gitignore` に入っているものは出ない） |
| `# branch.ab +A -B` | push していないコミット（A）。追跡するブランチがなければ行がなく 0。分岐元があるときの使い分けは下の「追跡するブランチと分岐元」。B（追跡するブランチからの遅れ）は、分岐元のない元のフォルダで取得がオンのときだけ使う（下の「表示」） |

印には、この 3 つをそれぞれアイコンと件数で並べます（0 のものは出さない）。

### 追跡するブランチと分岐元
分岐元（ワークツリーの割り出した分岐元と、元のフォルダが既定以外のブランチにいるときの既定のブランチ）があるときは、`arrow-up` の数を次のように決めます。どれも、分岐元との比べは `createBranchReader` の結果を使うので、git は増えません。

| 追跡するブランチ | push していない数（A） | `arrow-up` に出す数 | ツールチップ |
|---|---|---|---|
| ない | ― | 分岐元にまだ入っていないコミット | 「<分岐元> に未マージのコミット：n」 |
| ある | 1 以上 | push していないコミット | 「push していないコミット：n」 |
| ある | 0 | 分岐元にまだ入っていないコミット | 「<分岐元> に未マージのコミット：n」 |

- 3 つ目は、ワークツリーのブランチを push して PR を出したあとの形です。push していない数だけを出すと 0 になり、PR がまだマージされていないことが見えなくなるためです。
- 分岐元がないとき（元のフォルダが既定のブランチにいる）は、今までどおり push していないコミットだけを出します。

### 元のフォルダが既定以外のブランチにいるとき
元のフォルダ（ワークツリーでない作業フォルダ）でも、既定のブランチ以外にいれば、既定のブランチを分岐元としてワークツリーと同じように比べます。

- **既定のブランチ**：`.git` のファイルだけから読みます（git は起動しない）。順に `refs/remotes/<リモート>/HEAD`（`origin` を先に見る）の指すブランチ、手元の `main`、手元の `master`、記録の分岐元（`sourceBranch`）のうち、手元に `refs/heads/<名前>` があるもの。読んだ答えは `.git` の探索と同じく 60 秒使い回します。
- **分岐元にする条件**：今のブランチが既定のブランチと違う、またはブランチにいない（detached HEAD）とき。既定のブランチが決まらなければ、今までどおり分岐元なしで扱います。
- **割り出しはしない**：ワークツリーの分岐元はコミットのつながりから割り出します（`findBase`）が、元のフォルダでは既定のブランチをそのまま分岐元として待ち行列に渡します。元のフォルダの今のブランチは、たいてい既定のブランチから切ったものだからです。
- **遅れ**：分岐元があるときは、`arrow-down` に既定のブランチからの遅れを出します。取得がオンでも、追跡するブランチからの遅れには置き換えません。
- **マージ済み**：元のフォルダのカードは、マージ済みでも隠しません（印はマージのアイコンにします）。
- **ブランチにいないとき**：カードの名前を短いコミット ID にします。

### 数が 0 でも詳細を開く入り口
調べ終えていれば、数がすべて 0 でも印を出します。中身はブランチのアイコンを薄く 1 つだけにし、押すと git の詳細を開けます（既定のブランチにいて何もない元のフォルダでも、最近のコミットを見られるように）。ツールチップは「変更はありません」です。まだ調べていないフォルダには印を出しません。

### 失敗の表示
git が失敗したら、印の代わりに注意のアイコン（`circle-alert`）を出し、ツールチップに理由を出します。

| 理由 | 見分け方 | ツールチップ |
|---|---|---|
| タイムアウト | 5 秒で打ち切った（`killed`） | 「git が 5 秒で終わりませんでした」 |
| safe.directory | 標準エラーに `safe.directory` か `dubious ownership` | 「git がこのフォルダを信頼していません（safe.directory）」 |
| git が見つからない | `ENOENT` | 「git が見つかりません（PATH）」 |
| そのほか | 上のどれでもない | 「git の実行に失敗しました」 |

- 2 回続けて失敗したフォルダは、調べ直す間を 5 分に延ばします（ターンの終わりでも調べ直しません）。git が見つからない PC や、毎回タイムアウトする大きなリポジトリで、30 秒ごとに git を待たないためです。成功したら元の間隔に戻ります。

## いつ調べるか
セッションの一覧を読み直すたび（ファイルの変化と 30 秒おきの読み直し）に、次のフォルダだけを調べ直します。

- まだ調べていないフォルダ
- 結果が古くなったフォルダ：処理中か対応待ちのセッションがあれば 30 秒、待機中と停止中のセッションだけなら 5 分（待機中はターンの終わりに調べ直したあと、ファイルがほとんど変わらないため）
- 処理中のセッションが処理中でなくなったフォルダ（ターンが終わり、変更が増えたかもしれない）

調べ終えて結果が変わったら、一覧を画面に送り直します。作業フォルダを `fs.watch` で見張ることはしません（`node_modules` などで通知が多すぎるため）。

## 表示
今の色は状態だけを表すので、印は灰色の枠です（案 A）。中に内訳を lucide のアイコンと件数で並べます。

| アイコン | 意味 |
|---|---|
| `file-pen-line` | 変更 |
| `file-plus` | 未追跡 |
| `arrow-up` | push していないコミット |
| `arrow-down` | ワークツリー：元のブランチからの遅れ。元のフォルダ：追跡するブランチからの遅れ（取得がオンのときだけ） |

- カード（ワークツリーと元のフォルダ）の見出しの右。印の 4 つ目に遅れ（`arrow-down`）も出す
  - ワークツリー：手元の元のブランチと比べる。調べ方は [worktree-cards.md](worktree-cards.md) の「git：元のブランチからの遅れとマージ済み」
  - 元のフォルダ：設定でリモートの取得（[git-fetch.md](git-fetch.md)）をオンにしたときだけ、`# branch.ab +A -B` の B を出す。オフのときは `refs/remotes` の写しが古いままで数が実際と合わないので出さない
- ワークツリーのマージ済み：手元の元のブランチか、取得がオンならそのリモートの写し（`refs/remotes/<リモート>/<元のブランチ>`）のどちらかに、マージコミットで入ったとき。GitHub でマージしたものも、手元に取り込む前に分かる（squash マージは分からない）
- 印のツールチップ、セッションのツールチップ：「未コミットの変更：変更 3・未追跡 2」「push していないコミット：1」「元のブランチからの遅れ：4」。元のフォルダの遅れは「origin/main からの遅れ：3」
- すべて 0 のフォルダには薄いブランチのアイコンだけを出します（上の「数が 0 でも詳細を開く入り口」）。まだ調べていないフォルダには印を出しません
- カードの見出しの印を押すと、コミットの並びなどの詳細を開きます（[git-detail.md](git-detail.md)）
- 設定の「git」で、印を出さないようにできます（「カードに変更の印を出す」）。そのときも git status は動かし、マージ済みのカードの自動のアーカイブには使います。「未追跡のファイルを数える」をオフにすると、`--untracked-files=no` を付けて調べ、未追跡は 0 になります
