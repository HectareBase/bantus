# GPU（ハードウェア アクセラレーション）を使わない設定

ウィジェットのメモリを減らすため、GPU で描くかどうかを設定で選べるようにします。**既定は使わない**です。

## ねらい
ウィジェットのプロセスのうち、GPU のプロセスがいちばん大きいメモリを使っていました。Bantus の画面は文字、枠、半透明の塗り、CSS のアニメーションだけで、WebGL や動画を使いません。GPU がなくても、ソフトウェアの描画で足ります。

## 動かし方
- 設定の「全体」→「動作」→「GPU」（使う／使わない）。設定の名前は `hardwareAcceleration`（`app/src/shared/settings.ts`）
- メインプロセスは、起動したとき（`app` の ready より前）に設定を読み、使わないなら `app.disableHardwareAcceleration()` を呼ぶ。ready のあとでは切り替えられない
  - 設定はデータフォルダの `settings.json` から読む。ワークツリー版と見本データはデータフォルダを先に切り替えるので、その後で読む（`app/src/main/main.ts`）
- 設定を変えたら、その場で起動し直す（`app.relaunch()` → `app.quit()`）。新しいコードへの切り替え（`self-update.ts`）と同じ関数を使う
  - 起動し直したあとに設定ウィンドウを開き直すため、引数 `--bantus-open-settings` を付ける（`app/src/main/relaunch.ts`）
  - インストール版では、アプリのフォルダを引数に付けない（npm start のときだけ付ける）
- 使わないときは、起動オプション `in-process-gpu` も付け、画面の合成を GPU のプロセスでなくメインのプロセスの中で動かす。GPU のプロセス（40 MB ほど）がなくなり、メインのプロセスが 30 MB ほど増えるので、差し引きで private メモリが 10 MB ほど、ワーキングセットが 45 MB ほど減る
  - 使うときは付けない。付けると、Direct3D の描画面を作れないエラー（`EGL_BAD_ALLOC`、`0x887A0001`）が続けて出た

## 確かめた結果
見本データ（`all-states`、カード 17 枚、HTML ビューアあり、左端）で、GPU を使うときと使わないときを比べました。メモリは private メモリ、CPU は 1 コアに対する割合です。

### メモリ
| | GPU を使う | GPU を使わない |
|---|---|---|
| GPU のプロセス | 99〜126 MB | 21〜26 MB |
| 合計（起動して 15 秒） | 313〜318 MB | 233〜238 MB |
| 合計（起動して 45 秒） | 382〜386 MB | 302〜305 MB |

GPU のプロセスのほかは、ほとんど変わりません。実際のデータで動かしたときは、GPU のプロセスが 161 MB から 21 MB になりました。

### CPU（30 秒の平均、3〜4 回）
| | GPU を使う | GPU を使わない |
|---|---|---|
| アイドル（点滅や回転のアニメーションは動いている） | 10〜16% | 10〜13% |
| めくれを 0.75 秒ごとに出し直しているとき | 8〜15% | 11〜15% |

回ごとのばらつきのほうが大きく、差は見えません。ソフトウェアの描画でも、描く量が小さいので CPU は増えません。

### 見た目と動き
| 確かめたこと | 結果 |
|---|---|
| 透明なウィジェット（背景の不透明度 60%） | どちらも、後ろの画面が透けて同じに見える |
| めくれと一覧のウィンドウ | どちらも開き、同じに描かれる |
| HTML ビューア（`WebContentsView`） | どちらも描かれる |
| 設定ウィンドウ（`backgroundMaterial: 'mica'`） | どちらも同じに描かれる |
| アニメーション（処理中の回転、点滅、めくれの出し入れ） | どちらも動く |
| `capturePage` の撮影（`npm run debug -- --screenshot`、`npm run screenshots`） | どちらも撮れる |
| 撮影の画素の差 | 文字と枠の縁のアンチエイリアスだけ（最大 57/255）。形や位置のずれはない |
| 設定を切り替えたとき | 起動し直し、設定ウィンドウが開き直す。GPU のプロセスが 126 MB から 26 MB になった |

崩れるものは見つかりませんでした。このため既定を「使わない」にします。

### 確かめられなかったこと
- ツールチップのウィンドウは、撮影のときにフォーカスで出せなかった（GPU の設定とは関係なく、どちらでも出ない）。描き方はめくれと同じ透明なウィンドウ
- めくれの出し入れは、画面側にポインタのイベントを送って動かした。本物のカーソルではないので、めくれはすぐ閉じる。開いたままの状態は、重なりの的を押して確かめた
- 高い DPI の別のモニターや、Windows のリモート デスクトップでは試していない

## 戻すとき
描画が崩れる、動きがかくつくなどのときは、設定で「使う」にすると、起動し直して GPU で描きます。
