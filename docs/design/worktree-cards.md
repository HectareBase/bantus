# ワークツリー単位のカードと Bantus のアーカイブ

一覧を「リポジトリごとのカード」から「ワークツリーごとのカード」に作り替え、使い終わったセッションを Bantus の中だけでアーカイブして隠す。この文書は、作る前に確かめた実現性の結果と、作る仕様をまとめたもの。

## ねらい
使い方を見ると、次のことが多い。

- 同じワークツリーでセッションを同時に動かすことは少ない（ファイルがぶつかるため）
- main からワークツリーを作るので、main には使い捨ての質問やレビューのセッションがたまる
- ワークツリーで新しいセッションを始めるのは、コンテキストを小さくして作業を続けるため

そこで、1 つのワークツリーを 1 枚のカードにし、同じワークツリーの古いセッションは自動でアーカイブして、カードには今のセッションだけを残す。

### 考え方
- **事実だけで決める**：作業フォルダ、状態、最後に動いた時刻など、データで確かめられることだけを使う。どうやって作られたセッションかには頼らない
- **動いているものは隠さない**：処理中、対応待ち、未確認のものは、どの決まりでもアーカイブしない
- **間違えても戻せる**：アーカイブは Bantus の中だけで、いつでも戻せる。手で戻したものは勝手に隠さない
- 運用（引き継ぐときは同じワークツリーで新しいセッションを始める、など）は目安で、ずれても表示が崩れないことを優先する

## 実現性の確認

### `local_*.json` の項目
手元のデータを読むだけで数えた（値は見ず、項目の有無だけ）。

| 項目 | 結果 |
|---|---|
| `createdAt` / `lastActivityAt` | すべてのファイルにある |
| `spawnedFrom.sessionId` | 別のセッションから作ったものにだけある。サイドチャット（`btw`）を除くと、指す先はすべて手元に残っていた。ワークツリーのセッションの元は、どれも main のセッションだった |
| `turnWrapUp.description` | 7 割ほどのファイルにある（ターンを終えたことがないもの、古いものにはない）。ないときは下の段を出さない |

使える。`spawnedFrom` がなくても、時刻の順でつなぐ（破線）ので困らない。

### コンテキストの使用量
- `local_*.json` と `~/.claude/sessions/<pid>.json` には、使用量の項目がない
- 会話の記録（`~/.claude/projects/<フォルダ>/<cliSessionId>.jsonl`）の、最後のアシスタントの発言の `message.usage` から、使っているトークン数は出せる（`input_tokens + cache_read_input_tokens + cache_creation_input_tokens`）。サブエージェントの発言（`isSidechain`）は除く。ファイルは 1 MB を超えることがあるので、末尾だけを読み、大きさと更新時刻が変わったときだけ読み直す
- **分母（コンテキストの大きさ）はどこにもない**。リクエストの `max_tokens` は出力の上限で、コンテキストの大きさではない。自動の要約（`compact_boundary` の `compactMetadata.preTokens`）が 200k を大きく超えたところで起きた記録もあり、モデルから大きさを決め打ちするのも危ない

→ 割合（%）と「70% で黄色」は作れないので、**使用量は出さない**ことにした。会話の記録も読まない（[data-usage.md](data-usage.md) の「しないこと」のまま）。

### git：元のブランチからの遅れとマージ済み
今の `git status` と同じく `--no-optional-locks` を付けて読むだけにし、同じ待ち行列で一度に 1 つずつ動かす（[git-changes.md](git-changes.md)）。

- **元のブランチ**：`local_*.json` の `sourceBranch`（アプリが作ったワークツリーだけにある）。ないとき（`git worktree add` で自分で作ったもの）は、元のフォルダの今のブランチ（`mainBranch`）
- **遅れ**：`git rev-list --left-right --count <元>...HEAD` の左の数。右の数は元のブランチにまだ入っていないコミット
- **マージ済み**：右が 0（ワークツリーの先頭が元のブランチに入っている）で、しかも先頭が元のブランチの first-parent の線の上にないとき。調べ方は `git rev-list --first-parent --reverse HEAD..<元>` の最初のコミットの 1 つ目の親が、ワークツリーの先頭と違うこと
  - 作ったばかりでコミットのないワークツリーは、先頭が元のブランチの線の上にあるので、マージ済みにならない
  - マージコミットで入れたものだけを見分けられる。fast-forward、squash、リモートだけでのマージ（手元の元のブランチが古い）は見分けられない。そのときはカードを手でアーカイブする
- 手元のリポジトリで、マージ済みのブランチと作ったばかりのブランチを正しく見分けられた。1 回あたり約 50ms

### Electron：めくれと一覧の別ウィンドウ
小さな検証用のアプリで確かめた。

| 確かめたこと | 結果 |
|---|---|
| 置き方 | `tip-place.ts` の考え方（ウィジェットの外の画面の内側、縦は基準の上端にそろえて作業領域の中へずらす）をそのまま使える。違いは、めくれがカードの端から始まり、ウィジェットの余白に重なること |
| フォーカスを奪わない表示 | `focusable: false` で作り、`showInactive()` で出すと、前面のウィンドウのフォーカスは動かなかった |
| 表示の遅れ | 中身を送ってから描き終わるまで 5〜20ms、`showInactive()` は 1〜2ms。ツールチップと同じく「描き終えてから見せる」で、古い中身が一瞬見えることもない |
| クリックの透過 | `setIgnoreMouseEvents(true, { forward: true })` と `false` の切り替えは問題なく動く。透明な部分ではクリックが下（ウィジェット）へ通り、マウスの動きは一覧の画面にも届くので、めくれや一覧に乗ったら透過を止める |
| Esc と外のクリック | フォーカスのないウィンドウにはキーが届かない。**押して一覧を開いたときだけ** `setFocusable(true)` にしてフォーカスを移すと、Esc を受け取れ、ほかを押したときの `blur` で閉じられる（`blur` が届くことを確かめた）。閉じたら `setFocusable(false)` に戻す |
| CPU | ウィンドウは一覧が入る大きさで一度だけ置き、めくれから一覧への変形は中身の `transform` と `opacity` だけで動かす。コマごとに `setBounds` はしない |

マウスで実際に乗せたり外したりする操作（重なりからめくれへ移っても消えないこと）は、自動では試せないので、作ったあとに手で確かめる。

### 今の作りとの関係
| 今あるもの | どうするか |
|---|---|
| リポジトリのカードの中の、ワークツリーの小見出し | リポジトリ名はカードの上の見出しにし、ワークツリー（main を含む）ごとにカードを分ける |
| 折りたたみ（上限を超えた分と停止中） | なくす。隠すのはアーカイブだけ |
| 「グループごとの表示数」「折りたたみのまとめ方」の設定 | なくす |
| 「常に表示」の星（`alwaysShow`） | アーカイブのトグルで「手で戻した」状態に置き換える。保存されている星は、手で戻したものとして引き継ぐ |
| セッションの番号（`showSeq`） | 出さない（前にいくつあったかは重なりの件数でわかる）。設定もなくす |
| `Ctrl+Alt+N` の巡回 | 表示順で回るのは今と同じ。アーカイブ済みは画面にないので自然に外れる。main のカードは入る |
| 今開いている行の背景色 | ごく薄い斜めのストライプの透かしに替える |

## 仕様

### カード
- リポジトリごとに見出し（リポジトリ名と、要対応・処理中のバッジ）を置き、その下にワークツリーごとのカードを並べる。main（元のフォルダ）のカードも 1 枚。カードは見出しより 12px 字下げし、プロジェクトの中のワークツリーだとわかるようにする
- ワークツリーのセッションが作業フォルダを分けずに始めたセッション（`use_worktree: false`）は、`local_*.json` に `worktreeName` がなく、`gitAnchors` の `gitRoot` も元のリポジトリを指す。そこで `cwd` からワークツリーのフォルダを探し、アプリが作ったワークツリー（`worktreePath`）と同じフォルダなら、その目印（`worktreeName`）にそろえて同じカードにまとめる
- カードの見出しは、ブランチ名と git の印（変更、未追跡、push していないコミット、元のブランチからの遅れ）だけ。押しても何も開かない。乗せるとブランチ名の全体と作業フォルダをツールチップで出す
- git の印は今と同じ灰色の枠。遅れは `arrow-down` と件数。0 のものは出さない
- Claude が作るワークツリーのブランチには、ふつう追跡するブランチがない。そのときは `arrow-up` に、push していないコミットの代わりに元のブランチにまだ入っていないコミット（`rev-list --left-right --count` の右の数）を出す。ツールチップは「元のブランチにまだ入っていないコミット：n」
- マージ済みのカード（手で戻して出しているとき）は、内訳の代わりにマージのアイコン（`git-merge`）だけを出す

### アーカイブの決まり
アーカイブは Bantus の設定に保存し、デスクトップの `isArchived` には書かない。セッションが消えたら設定からも外す。

1. **動いているものは出す**：処理中、対応待ち、未確認（左端の帯）のものは、手でアーカイブしたものでも出す。手でアーカイブしたものが動き出したら、手の印を外して自動の決まりに戻す
2. **手で戻したもの**は、もう一度押すまで出す
3. **手でアーカイブしたもの**は隠す
4. **ワークツリー**：同じワークツリーで `lastActivityAt` が一番新しいものを残し、ほかの落ち着いたもの（待機か停止中で、確認済み）をアーカイブする
5. **main**：落ち着いてから一定の時間（既定 10 分。設定で 10 分・30 分・1 時間・しない）がたったものをアーカイブする。時間は「最後に動いた時刻」と「ウィジェットで確認した時刻」の新しいほうから数える（確認した時刻はウィジェットの中だけで覚える）
6. **起点**：main のセッションから `spawnedFrom` で作られたワークツリーのセッションがあれば、その main のセッション（起点）は、落ち着いていればワークツリーのカードのアーカイブに入る（main のカードからは消える）
7. **マージ済みのワークツリー**はカードごとアーカイブし、リポジトリの見出しに件数を出す。カードも手でアーカイブ・戻しができる

アーカイブしたものは画面に出ないので、`Ctrl+Alt+N` の巡回にも入らない。

### 行
- 状態のアイコンとアーカイブのトグルは、行（題名と下の段）の縦の真ん中
- トグルは行の右端に 1 つ。ウィジェットでは乗せたときだけ出し、一覧ではいつも出す。アーカイブ中かどうかで濃さや塗りを変えない。戻ったものに印は付けない
- 処理中・対応待ちの行はアーカイブできない（動いているものは隠さない）ので、トグルを出さない。そうした行があるカードの見出しにも、カードのトグルを出さない
- 下の段：「◯分前」（設定で出す・出さない）。コンテキストの使用量は出さない
- 今開いているセッションの行は、マウスを乗せたときと同じ濃さにし、ごく薄い斜めのストライプ（明るいテーマで黒の 2.5%、暗いテーマで白の 3%）を重ねる。乗せたときは一段濃くする。色相は使わない。一覧の中でも同じ

### 入り口：重なりとめくれ
- 以前のセッション（アーカイブ）があるカードだけ、後ろに紙を 1 枚重ねたように描く。件数にかかわらず 1 枚で、カードの高さは変わらない。起点を手で戻して main に出したときも、つながりは一覧で見られるので重なりを残す（件数は、一覧にあってそのカードの行に出ていないもの）
- 重なりは画面の内側（ウィジェットが右端なら左）に、ウィジェットの余白（8px）いっぱいまで見せる。カードより一段濃い灰色
- 押せる的は見えている幅より広く取り、ウィジェットの端まで透明な的を重ねる
- 重なりに乗せると、別のウィンドウに「めくれ」（件数と矢印）を出し、0.15 秒でウィジェットの外へ伸ばす。めくれは重なりと同じ灰色で、カードの端から重なりを覆って続く。めくれはカードの高さによらず、カードの上端から 6px 下にそろえた高さ 32px のつまみにする（低いカードでは中に収める）。カードが長いときに細長い帯になると、件数がブランチ名から離れ、目を引きすぎ、一覧への変形も縦に大きく縮む動きになるため。隠れている重なりと乗せる的も、同じ高さのつまみにする（隠れているつまみが飛び出してめくれになる）。飛び出す幅はカードの端から 18px で、隠れている重なり（見えている幅 6px、ウィジェットの端から 2px あける）のおよそ 2 倍。めくれから外れたらすぐに消す（動きは付けない）
- めくれが隠れていても、めくれが飛び出す所（ウィジェットの外にはみ出す所も含む）にカーソルを置けば出す。反応する範囲は、重なりの的と、めくれ（つまみ）が飛び出す所の 2 つの四角（`shared/flap.ts` の `flapRect`）。1 つの四角にまとめると、長いカードではつまみのない所まで反応してしまうため
- めくれを押すと、その形のまま一覧へ 0.22 秒で変形する。閉じるときは動きを付けずにすぐ消す。一覧はめくれと同じ端（カードの端）から、めくれの形（伸びる動きを除いた形）を起点に広がる。めくれと重なりが飛び出して一覧になったものとして、開いている間はめくれとそのカードの重なりを隠す
- 動きを減らす設定（`prefers-reduced-motion`）のときは、動きを付けずに切り替える

### 一覧
- ウィジェットの横（画面の内側）に、ウィジェットの端から 3px あけて出す。めくれはカードの端から伸び、そこから一覧の位置へ変形する。縦はカードの上端にそろえ、はみ出すときは中へずらす。ウィジェットのカードは隠さない
- ブランチの見出しは出さない（カードにあるため）
- 中身は縦のタイムライン。新しく作ったものが上で、一番下が起点（◇）。`spawnedFrom` でつながるものは実線、時刻の順で並べただけのものは破線。わき道（同じセッションから 2 つ作ったものなど）を枝で描くのは後に回し、今は 1 本の線に並べる
- 行に乗せてカーソルを動かすと、一覧の下の段に最後のターンのまとめ（`turnWrapUp.description`）を出す。開いたときは一覧がカーソルの下に広がるので、開いて変形している間と、カーソルを動かすまでは出さない
- 行を押すとそのセッションを開いて閉じる。重なりのあった所を押す、Esc、外のクリックでも閉じる。開けるのは 1 つだけ
- 開いている間も、ほかのカードの重なりは反応する。乗せて少し（0.15 秒）とどまると、開いている一覧を閉じて、その重なりのめくれを出す。一覧からウィジェットへカーソルを戻すときに、通りがかった重なりで閉じないよう、とどまるのを待つ
- main のカードの一覧は、アーカイブした質問と、ワークツリーのカードへ移した起点を新しい順に並べる（線はない）。起点は main で始めたセッションなので、main からもたどれるようにする
- リポジトリの見出しの件数を押すと、マージ済みのワークツリーの一覧を同じウィンドウに出す

### ウィンドウの作り
コードは `app/src/main/flyout.ts`（置き方と出し入れ）と `app/src/renderer/flyout.ts`（中身と動き）。

- めくれと一覧は 1 つの透明なウィンドウ（`flyout.html`）。最前面に置き、ウィジェットと一緒に出したままにして、めくれと一覧は中身（CSS）だけで出し入れする。乗せるたびにウィンドウを出すと、Windows の表示のアニメーション（下から浮き上がる動き）がかかり、カードの端から伸びるように見えないため。ふだんはクリックをすべて下へ通す
- ウィンドウはカードの端（画面の内側の端）から外へ、作業領域の高さいっぱいに置く（`tip-place.ts` の `flyoutBounds`）。縦の位置は中身の画面が決めるので、開いたあとにウィンドウを動かすことはない
- 乗せたとき：ウィジェットの画面が、カードと重なりの的の位置、件数、一覧の中身をメインプロセスへ送る → 中身を送る → 中身の画面が描き終えて「クリックを受け取る場所」（めくれと一覧の四角）を返したら、カーソルを見始める。ウィンドウの場所はカードによらず同じなので、ウィジェットの幅や端が変わったときだけ置き直す
- ウィジェットが出ている間は、メインプロセスが 30ms ごとにカーソルの位置を見る。ウィジェットの外はウィジェットの画面からは見えないので、ウィジェットの画面がめくれの飛び出す所（見えているカードの分）を描き直しやスクロールのたびに送り、カーソルがウィジェットの外でその範囲に入ったら、ウィジェットの画面に知らせてめくれを出してもらう。めくれや一覧の上では、ほかのカードの範囲に重なっていても反応しない。
- めくれを出している間は、受け取る場所の上ではクリックを受け取り、ほかでは下へ通す（`setIgnoreMouseEvents(true, { forward: true })`）。めくれだけのときは、重なりに反応する範囲とめくれのどちらからも外れたら、すぐ消す。的はカードの中へ少しかかっていて、めくれのウィンドウの外にあるので、めくれだけを見るとウィジェット側からゆっくり乗せたときにすぐ消えてしまう。的の上で動いている間にめくれが消えていたら、ウィジェットの画面が出し直す
- フォーカスを取れるウィンドウにして、`showInactive()` で出しておく（乗せただけではフォーカスを取らない）。押して開いたときにフォーカスを取り、`blur`（外のクリック）と Esc で閉じる。Windows が前面に出すのを断ったときは、開いている間だけ Esc を登録する
- `setFocusable` で切り替えるのはやめた。Windows では、一度切り替えたあと、めくれの上のクリックが下のウィジェットへ抜けるようになった
- Windows では、最前面のウィンドウどうしの上下は最後に触ったもので決まり、Electron の高さの指定（`pop-up-menu`）は効かない。ウィジェットを押したあとや一覧を閉じたあとは、ウィジェットがめくれより上に来て、重なりの上のクリックをウィジェットが受け取ることがある。そこで、見せるときとカーソルがめくれに入ったときに一番上へ上げ直し、それでもウィジェットの重なりが押されたときは、めくれを押したときと同じく一覧へ変形させる（どちらに届いても同じ動きになる）
- 外のクリックで閉じた直後（0.4 秒）は、同じ重なりへのクリックで開き直さない（開いているときにウィジェット側の重なりを押すと閉じる）。めくれは一覧の下に隠れるので、一覧が開いているときにめくれのあった所を押すと、一覧の行を押したことになる
- 一覧の中の操作（行を押した、トグルを押した）はウィジェットの画面へ渡し、ウィジェットの画面が保存と描き直しをして、新しい中身を送り直す
- ウィジェットが動いた、大きさが変わった、隠れた、一覧をスクロールしたときは消す
- 見本データでは `npm run debug -- --screenshot <保存先> --fly <セレクター>` で、押して開いた一覧も撮れる

## 手で確かめること
- 重なりに乗せるとめくれがカードの端から伸びて出て、重なりからめくれへ移っても消えないこと。ウィジェット側からゆっくり乗せても出ること。めくれが隠れているときに、ウィジェットの外のめくれが飛び出す所へ乗せても出ること。外れたらすぐ消えること
- めくれを押すと一覧へ変形し、Esc、外のクリック、重なりをもう一度押す、行を押すで閉じること
- ほかのアプリが前面にあるときにめくれを押しても、Esc と外のクリックで閉じられること

検証では、見本データのウィジェットを別のデータフォルダ（`--user-data-dir`）で起動し、PowerShell からカーソルを動かして押し（`SetCursorPos`、`mouse_event`）、DevTools のプロトコル（`--remote-debugging-port`）で一覧の画面の状態を読んだ。ウィジェットを右端に置き、ウィジェットを一度押してから、乗せる・めくれを押す・もう一度押す・乗せ直して押す・外を押すを 3 回繰り返し、どれも決めたとおりに動いた。メインプロセスの出し入れは、環境変数 `FLY_DEBUG` を付けるとコンソールに出る

## 設定の変わり方
| 項目 | 変わり方 |
|---|---|
| `groupLimit`、`foldScope`、`showSeq` | なくす（保存されていても読み捨てる） |
| `alwaysShow` | `archive`（セッションの ID → 手でアーカイブ／手で戻した）に移す |
| 新しく `archivedCards` | 手でアーカイブ・戻ししたカード（ワークツリーの目印 → 状態） |
| 新しく `mainArchiveMinutes` | main で自動でアーカイブするまでの分（10 / 30 / 60 / 0 はしない） |
