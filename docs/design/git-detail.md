# git の詳細（カードの見出しの印を押したとき）

カードの見出しの git の印（変更の件数、↑、↓。[git-changes.md](git-changes.md)）を押すと、めくれのウィンドウ（[worktree-cards.md](worktree-cards.md) の「ウィンドウの作り」）に、そのカードの git の詳細を開きます。新しいウィンドウは作らず、めくれの中身の種類（`FlyContent`）に `kind: 'git'` を足しています。

コードは `app/src/main/git-detail.ts`（読む）、`app/src/renderer/flyout-git.ts`（描く）、`app/src/renderer/renderer.ts` の `showGitFlyout`（開く）です。

## 見た目（枝の図）
幅は一覧と同じ 300px。丸と線はタイムライン（13px の丸、2px の線、◇ の起点、高さを固定した下の段）にそろえ、色は灰色だけにします（色は状態を表すため）。

| 場所 | 中身 |
|---|---|
| 見出し | ブランチのアイコンと短いブランチ名（カードの見出しと同じ。全体はツールチップ）。ワークツリーなら `› main` のように分岐元を続ける。札は、図に出ないものだけにする：メインのカードで取得がオンのときの ↓（追跡するブランチからの遅れ）と、マージ済みの札。↑ の数は図の件数で分かるので出さない |
| 一番上 | コミットしていない変更があるときだけ、点線で中が空の丸。題名は「コミットしていない変更」、2 行目は「変更 N・未追跡 N」。下へは点線でつなぐ |
| その下 | 分岐元にないコミットを新しい順に。HEAD は中が空の丸、ほかは塗った丸。件名が `<種別>(<範囲>): <要約>` の形なら、種別と範囲を札（`feat · app`）に、要約を本文にする（合わなければ件名のまま）。2 行目は短い ID と相対時刻だけ |
| 一番下 | 分岐元を ◇ で。図の端の印なので、題名「ここから分岐」はコミットより控えめにし、2 行目に分岐元の名前、分岐点の短い ID、分岐元が先に進んでいれば「その後 N 件進んでいる」 |
| 下の段 | 高さは固定（一覧の下の段より 1 行高い）。乗せた行のコミットの短い ID と日時を 1 行目に、本文を 4 行に出す。件名は乗せている行に出ているのでくり返さない。本文が収まらなければ、下の段の上のホイールで本文を送る。乗せていないときは全体の件数 |

- コミットの行を押す（または Enter／Space）と、短い ID をクリップボードに写し、2 行目に「ID をコピーしました」と少しのあいだ出す。写すのはメインプロセスで、ID の形（16 進）のものだけ。押せるのはコミットの行だけで、ほかの行は乗せても塗らない
- コミットの行のツールチップには、件名と本文の全体、コミットした日時（その環境の書き方）を出す。画面にはいつも相対時刻だけを出す
- コミットが 2 件以下のときは、下の段を出さず、本文を行の中に 3 行まで出す（段のほうが図より大きくなるため）。丸と線はその行の題名にそろえる。読み込み中と読めなかったときは、下の段で知らせる
- コミットが 8 件を超えるときは、先頭の 2 件と、分岐元のすぐ上の 1 件だけを出し、間を「ほか N 件」とたたむ。押すと全部出す。開き直すとたたんだ状態に戻る
- 上限（50 件）で切ったときは、たたんだ行の数に切った分も含め、分岐元のすぐ上の 1 件は出さない。広げたときは最後に「ほかに N 件（表示は 50 件まで）」と出す
- マージ済み：見出しを `git-merge` のアイコンと「マージ済み」の札にし、一番上に ◇（「ここにマージ済み」と、マージした先）、コミットは薄く出す
- メインのカード（ワークツリーでない）：最近のコミットを 5 件。◇ は出さない
- コミットの件名と本文はリポジトリから来た文字なので、`textContent` だけで出す

## 軽さ
ユーザーの指示で、できるだけ軽く動かします。

- **増減（+/− の行数）は出しません**。`--numstat`、`--stat`、`git diff` は使いません
- git は印を押したときだけ動かします。定期的に調べ直しません
- 動かすのは、ふつう `git --no-optional-locks log --format=... <分岐元>..HEAD -n 51` の 1 回だけです。分岐点は並びの一番古いコミットの親から取ります。コミットがないときと上限で切ったときだけ `merge-base`（と `rev-list --count`）を足します。マージ済みのときは、マージした先の first-parent の線で HEAD を取り込む前のコミットを `rev-list --first-parent` で探してから数えます（`git-status.ts` のマージ済みの見方と同じ）
- 変更の件数は、すでにある `GitChanges`（`git status` の結果）を使い、ファイルの一覧は取りません
- 結果は作業フォルダごとに、HEAD と分岐元（マージした先）の先頭のコミットの組で覚えて使い回します。先頭は `readRefs` で `.git` のファイルから読み、git は起動しません。先頭を読めないときと git が失敗したときは覚えません
- 呼び出しは `git-status.ts` の `git()`（タイムアウト 5 秒、`windowsHide`、`GIT_OPTIONAL_LOCKS=0`）を使います。本文は 1000 字で切り、末尾のトレーラー（`Co-Authored-By:` など）は除きます
- 150ms 以内に読めたら読み終えてから開き、遅いときは先に「読み込んでいます…」で開いて、読めたら差し替えます

## 作り
- 画面からはカードの目印（`key`）だけを受け取ります（`ipcMain.handle('git-detail')`）。作業フォルダと分岐元は、メインプロセスがセッションから決めます（画面が任意のフォルダで git を動かせないように）
- めくれの目印は `git:<カードの目印>` にして、見出しに乗せたときに出すタイムラインのめくれと区別します。詳細を開いている間は、同じカードの見出しに乗せてもタイムラインのめくれに切り替えません
- 印は `click` と Enter／Space で開きます。どちらも `stopPropagation` してから開きます。閉じるのは、めくれのほかの一覧と同じく、外のクリックと Esc です。開いたまま印をもう一度押すと閉じます（外のクリックで閉じた直後に同じものを開き直さない仕組みによる）
- 見本データ（`npm run debug`）では git を動かさず、見本の隣の `git-detail/details.json` から作ります
